# Introduction Opening Patterns

Use these patterns for the first one or two introduction paragraphs.

## Task First, Then Applications

Use when the task is niche.

Skeleton:

`[Task] aims to [output/action] from [input/source]. This setting is important for [application 1], [application 2], and [application 3], where [target requirement] is critical.`

Check:

- Does the first sentence define the task?
- Are applications specific enough to justify the problem?
- Does the paragraph move quickly toward the paper's challenge?

## Applications First

Use when the task is familiar.

Skeleton:

`[Application area] increasingly requires [capability], such as [example 1] and [example 2]. These applications demand [target metric/behavior], yet current systems still struggle under [condition].`

Check:

- Avoid textbook history.
- Mention the desired behavior before discussing methods.

## General Task To Specific Setting

Use when the paper studies a new setting under a known task.

Skeleton:

`[General task] has enabled [applications]. This paper focuses on [specific setting], where the goal is to [output] from [input] under [constraint].`

Check:

- The specific setting should not appear as an afterthought.
- Define the boundary of the setting early.

## Open With Challenge

Use when readers already know the task and the failure case is the hook.

Skeleton:

`Despite strong progress in [task], current methods often fail when [condition]. This failure is important because [consequence]. The root difficulty is [technical reason], which prevents [desired behavior].`

Check:

- The challenge must be precise.
- Do not use this pattern if readers need a task definition first.
